# 概念学习资料生成 Skill

## Overview

把任意一个「新概念」转化为一份结构化、可溯源、可直接用于学习/复习的深度学习资料。本 Skill 概念无关（concept-agnostic）——输入可以是技术术语（反向传播、RAG）、方法论（贝叶斯定理、第一性原理）、业务概念（LTV、飞轮效应）、学术或跨学科名词等任何单一概念。它强调：**先让用户真正"懂"，再让用户能"辨别"，最后让用户能"验证自己懂了"**，而非堆砌百科式罗列。

## 触发与不触发

**应触发：** 用户点名某个概念并要求学习/理解/讲解，例如
- "帮我学习一下『扩散模型』"
- "给我讲清楚什么是『因果推断』，我要能复述"
- "整理一份关于『向量数据库』的学习资料"

**不应触发：** 需要多概念横向综述的整篇论述、与"深入学习单概念"无关的开放性写作、只需一句话定义的即时词典查询。若用户要求的是这类内容，直接以常规方式处理，不进入本流程。

## 输入要求

### 必需输入
1. **目标概念**（required）：要学习的概念名称，可为中文或英文。示例：`反向传播 (Backpropagation)`。

### 可选输入（缺失则自行合理设定并在开头标注假设）
2. **受众背景**：零基础 / 有某领域基础 / 需应试，默认按"零基础但愿意投入"处理，若用户明确给出则优先遵从。
3. **学习深度**：入门了解 / 系统掌握 / 应用导向，默认"系统掌握 + 应用导向"。
4. **使用语言**：默认与用户当前语言一致。
5. **来源语言偏好**：默认优先中文易得来源，辅以英文权威来源。

> 若目标概念含歧义（多义术语、同名不同物），先向用户确认所指的是哪一含义；若无法即时确认，列出最可能的 1–3 个含义并选择最常见者作为主线，同时在其他含义说明中标注。

## 生成步骤（Workflow）

按顺序执行，每步输出为最终文档的对应章节，完成所有步骤后再汇成一份连续文档。

### Step 1 — 界定概念与澄清歧义
- 复述你对该概念的理解，一句话定义它。
- 识别所属学科/领域、它回答的核心问题、以及与之相邻的相近概念（为 Step 4 准备）。
- 若存在歧义，按上述输入规则处理。

### Step 2 — 资料采集（资料来源要求）
- 对本概念做**网络检索**，至少覆盖：官方/权威文档、学术或技术一手资料、被广泛引用的科普/综述、以及一个反面/批判性视角（如有）。
- 优先信源优先级（从高到低）：
  1. 官方文档、标准规范、学术论文/预印本；
  2. 权威机构、知名教材、领域公认专家；
  3. 高质量综述/博客/技术专栏；
  4. 低质、营销、或二手转述内容**只能用于佐证，不作为事实依据**。
- 对**每一个关键论断/机制/数据**记录其出处 URL，供 Step 5 引用。
- **若某个关键点无法找到可靠来源，明确标注"待核实"，不得编造出处。**
- 检索需校验时效：涉及快速发展领域（AI、框架、法规）时，优先选用最近 1–2 年内的资料。

### Step 3 — 内化与个人解释
- 抛开原文，**用自己的话**重新讲一遍：把概念比作日常生活中熟悉的事物（打比方）、用一句话提炼本质、说明"如果我要在 30 秒内教会一个外行，我会怎么说"。
- 强调这是"你的理解"，刻意与标准定义形成区分，帮助读者建立直觉而非死记。

### Step 4 — 结构化展开（撰写各核心章节正文）
基于采集到并经你内化的内容，撰写：核心机制 / 应用场景 / 边界辨析 的正文。

### Step 5 — 整理来源
- 汇总 Step 2 记录的所有出处，按"权威一手 > 综述科普 > 参考资料"分类列出。
- 每条给出：标题 + 平台/机构 + URL。URL 必须为你在 Step 2 实际检索到并可复现的链接，**禁止占位或虚构**。

### Step 6 — 生成学习路径与自测
- 设计一条从浅入深的学习路径（依赖前置知识 → 分阶段里程碑）。
- 产出用于检验理解的自测题与常见误区清单。

### Step 7 — 自检（自检要求）
- 逐项核对该 Skill 底部《自检清单》，确认输出结构完整、关键论断均有来源、无占位链接、边界/误区清晰。
- 未通过项需修正后才输出最终文档；无法修正处须向读者显式标注局限。

## 输出结构

最终交付物为一份连续文档，**固定包含以下章节**（顺序与标题保持不变，标题可随语言相应翻译）：

1. **个人解释（用自己的话）**
   - 一句话本质 + 生活化比方 + 30 秒教外行版 + 与你已有知识的一个关联锚点。
2. **核心机制（How it works）**
   - 概念背后的原理/流程/关键组件，用分步或分块讲清"它到底怎么运转"，配合可运行的最小示例或走查示例（示例代码需为可直接运行的骨架，而非贴段代码却不解释）。
3. **应用场景（When/Where to use）**
   - 3–6 个典型落地场景，各配一句"为什么适合这里、不适合哪里"。
4. **边界辨析（Limits & 易混辨析）**
   - 此概念**不适用/会被误用**的情形；与相近概念逐条对比差异（可用对照小表：对比维度 / 概念A / 概念B）；前提假设与失效条件。
5. **来源链接**
   - 按权威一手 > 综述科普 > 参考资料分组的真实链接清单，标注每条的价值。
6. **学习路径（进阶建议）**
   - 前置知识 → 入门(第1步要做什么) → 上手(小实践) → 深入(读原文/复现) → 产出(能教别人/做项目)。
7. **自测与常见误区**
   - 5–8 道自测题（附答案与解析）；3–5 条"新手最容易犯的错误"，帮你自查是否真正学会。

> 若某章确实不适用（例如概念太过简单无边界辨析价值），可精简但需说明原因；不得整章缺省而不说明。

## 语言与文体要求

- 用与用户一致的交流语言书写；术语首次出现时给出中英对照。
- 文体：清晰、具体、不空话。每个抽象说法尽量给一个可举的例子。
- 代码/公式示例必须可运行或数学上自洽，并附简短解释。

## 自检清单（输出前必须逐项核对）

- [ ] 输出包含全部 7 个固定章节，标题顺序一致。
- [ ] 「个人解释」确为我的转述，非照抄定义。
- [ ] 每个关键机制/数据/论断均能在「来源链接」中找到对应出处。
- [ ] 「来源链接」中的 URL 均真实可复现，无占位符、无虚构、无断链痕迹。
- [ ] 「边界辨析」至少含一条"此概念常被误用于的负面场景"。
- [ ] 「自测」附有答案与解析，非开放性问题无答案。
- [ ] 涉及快速演进领域时，信源为近 1–2 年内资料。
- [ ] 对检索中无法证实的关键点，已显式标注"待核实"而非硬写。
- [ ] 全文与用户语言/受众背景/学习深度假设一致（若有假设，已在开头声明）。

全部通过才交付；否则先修正，修正不了的以脚注/括号向读者说明局限。
